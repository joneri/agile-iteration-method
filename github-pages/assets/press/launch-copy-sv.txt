AIM 4.0
Börja med människorna. Leverera det som gör skillnad.

Förslag till lanseringstext · AIM 4.0 · 12 oktober 2026.

AI kan hjälpa oss att bygga mer mjukvara. AIM börjar med en annan fråga: vems problem löser vi?

AIM 4.0 sätter User Stories i centrum för AI-assisterad utveckling. En intention kan rymma flera Epics och flera människor med olika behov. Behoven blir Stories med tydligt värde och acceptanskriterier, som prioriteras tillsammans.

Product Owner äger kraven och prioriteringen. Technical Delivery Owner hjälper till att förfina Stories och planerar en sammanhängande leverans. Utvecklare implementerar, en separat Reviewer granskar och valideringen knyter resultatet till kriterierna. Användaren accepterar leveransen.

I AIM UI är Stories korten som rör sig över brädan. Epics håller de större målen synliga. Samma leverans kan innehålla Stories från olika Epics; inkrementet är den fungerande förbättring som leveransen ger. Done betyder accepterat beteende.

För utvecklare och produktteam som använder Codex, GitHub Copilot eller Claude Code erbjuder AIM en gemensam metod från idé till mjukvara som människor kan utvärdera och acceptera.
