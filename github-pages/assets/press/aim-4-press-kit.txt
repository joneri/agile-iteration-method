ONE SENTENCE
AIM connects the people you build for with the software you deliver, giving AI-assisted development a clear path from intent to accepted User Stories.

SHORT DESCRIPTION
Agile Iteration Method (AIM) is an open-source method and tooling for AI-assisted software development. AIM puts User Stories at the centre: start with an intent, identify the outcomes and people involved, then prioritize their needs across Epics. Product Owner, Technical Delivery Owner, Developer and Reviewer responsibilities connect planning to implementation, independent review and validation. Evidence supports the result; the user decides what is accepted.

WHAT CHANGES IN 4.2
- Shared guidance helps agents continue within the current assignment and reuse applicable prior answers and authority across sessions.
- Necessary questions show a recommended option first; dependent questions wait until their prerequisites are settled.
- An optional stateless helper checks reply scope and rejects stale or conflicting receipts. It records no decisions and grants no acceptance.
- Legacy cleanup handles external provenance citations without reading or deleting outside the project.

THE AIM 4 FOUNDATION
- Start with an intent. The Product Owner identifies the relevant Epics and owns Story value, acceptance criteria and priority. The Technical Delivery Owner helps refine the Stories and plans delivery.
- Select Stories across Epics. One delivery can meet several people’s needs while each Story keeps its own Epic and acceptance criteria.
- See Stories move through the local AIM UI. Epics group outcomes; Stories are the work cards. The UI reflects recorded lifecycle transitions.
- Make acceptance explicit. A working increment is the result of delivery. Done records acceptance of verified Story behaviour; Epic closure is a separate decision. A Sprint is an optional timebox.

EXAMPLE
A new customer wants to try sample data. A support specialist wants a useful failure reference. Those Stories can belong to different Epics and be delivered together, creating a first experience that is useful and recoverable.
