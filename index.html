Agile Iteration Method

Build your product from an intent.

Describe what you want in plain language. AIM turns it into requirements, a plan and working software, with agents configured for your project. Test the important behavior early, follow development in AIM Control, and approve increments backed by review and real results.

Start with what you want to build

Bring the idea. AIM organizes the development.

You do not need to write a backlog or coordinate every agent yourself. Describe the product and let AIM turn the goal into work that can be built, tested and accepted.

Example product intent

/aim start "Build a booking app where customers can find available times, book appointments and manage their bookings."

  1. Define the product.

    The Product Owner defines Epic outcomes, audience, quality and product priority. Existing requirements and decisions guide the work.

  2. Plan the next increment.

    The Technical Delivery Owner creates User Stories and acceptance criteria, then agrees the quality goals and checks for a coherent working result.

  3. Prove the core, then build.

    A separate reviewer challenges the first working core before costly expansion. The developer completes the plan; review and validation check the real user journeys and retained test results. Failed checks send the work back for correction.

  4. Approve and keep building.

    Accept the verified increment, then continue toward the full product. AIM keeps the goal, decisions and delivery history available across sessions.

A whole product is the goal. Small, reviewable increments are how you get there.

Repository-aware development

Your agents should know the project they are building.

AIM gives agents reusable project knowledge, a focused view of the code and skills suited to their roles. Each task starts with relevant facts, clear responsibilities and checks for the result you want.

Repo profile

Keep project knowledge between sessions.

Calibration records your stack, conventions, build and test commands, important code areas and risk zones in a repository profile. The next session can reuse those facts instead of discovering the project from scratch.

aim.profile.yaml holds reusable knowledge. AIM checks the affected facts when the project changes.

Localities

Give each task the context it needs.

Localities map areas of your codebase to their responsibilities, files, tests and dependencies. A maintained map of user journeys connects important behavior to runnable checks, so later work can reuse the same verification route.

Compact checkpoints and unchanged results are reused when their scope and dependencies still match. New risks or changed behavior trigger fresh checks.

Project agents & skills

Configure specialists for your stack.

AIM can create project-specific agents for product ownership, technical planning, development and review. Each role has a defined responsibility, relevant project knowledge and skills selected for the work.

/aim configure-agents sets up native specialists for Codex, Claude Code or GitHub Copilot, using the skills available to your project.

AIM recalls relevant shared lessons while planning, reviewing and diagnosing failures. Verified reusable corrections feed that shared advice during ordinary work. Focused context and reuse are designed to avoid repeated effort; their cost benefit depends on the work.

AIM Discuss

Talk to your code. Understand what you can build next.

Ask how a feature works, why the code is structured a certain way or what a proposed change would affect. AIM follows the relevant code and project context to help you understand the answer and weigh your options.

Use Discuss in your coding agent’s chat to explore an idea before committing to it. It reads and explains the project without changing the code or starting a delivery.

Try a question about your project

/aim discuss "How does booking cancellation work, and what would need to change to support rescheduling?"

Follow up, challenge an assumption or explore another approach. When you are ready to build, turn the decision into an intent with /aim start.

Install from a local checkout

Preview before changes. Clone the source and inspect the installation plan.

git clone --depth 1 https://github.com/joneri/agile-iteration-method.git aim-source
cd aim-source
python3 scripts/aim_install.py --dry-run

Review the plan before using --apply. Read the installer guide.

Already using AIM?

Run /aim upgrade to update AIM-owned files while preserving delivery history. Use /aim calibrate-repo to refresh repository context and /aim remember-repo to retain useful project facts. Shared learning is part of ordinary delivery; the old reflect and reflect-all names are retired compatibility aliases.
