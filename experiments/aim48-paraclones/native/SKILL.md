# AIM 4.8 Native experimental orchestration

Read `references/experiment-governance.md` and `brief.json` once. The bundled AIM
product contracts remain available under `references/`. Use this Native layer
for graph design and orchestration; do not substitute Superpowers or use it as
hidden planning advice.

Activate actual coordinating session and `aim-native-orchestration` version1
against the existing product outcome. Use `scripts/aim_orchestrate.py` to create
or validate the outcome-linked work graph from the actual inputs. Choose the
smallest useful default or preserve a supplied valid graph. Nodes describe
useful work/proof, not a required new agent per role.

Give one cohesive product author an end-to-end mandate unless implementation
branches are genuinely independent with disjoint writes. Reuse one independent
reviewer for the first consequential core challenge and material final review.
Do useful work while children run. Pass only needed requirements, paths, inputs,
expected outputs and verification. Do not approve each coding/math substep.

Start with a runnable baseline and smallest integrated route through the real
entry. Preserve the last usable checkpoint. Complete the remaining original
outcomes and verify them together; a component pass does not close a level.

Use `scripts/aim_orchestrate.py assess` at consequential continuation boundaries:
same outcome, evidence history, task-proportional no-progress attempt budget,
waiting goals and cumulative resources/unknowns. Local successes, activity names,
new sessions, hashes and active heartbeats do not reset campaign stagnation.
Bounded real information gain may justify hard debugging. When marginal value
stalls, change the concrete action: preserve usable route, address larger blocker
or independent waiting goal, or request a genuinely necessary owner decision.
Keep real crashes/frozen input as blockers; respect actual owner tolerance for
minor defects without weakening mandatory criteria or inventing acceptance.

Use native host delegation tools for actual dispatch and retain returned session
IDs. Helpers validate/recommend, not launch/authenticate agents. The coordinator
must apply their result at the real dispatch boundary; disclose failure to do so.
Graph/assessment output belongs in existing `.aim/analysis/` evidence and links to
the canonical product record, not a parallel product backlog. Resume must retain
outcome/history and reconcile uncertain calls rather than repeat completed work.
