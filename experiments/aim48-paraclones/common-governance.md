# Shared AIM product contract for the paired experiment

Use the frozen `brief.json` as the actual owner's product commitment. All three
levels and their real capabilities matter. Preserve original criteria, negative
results, source identity and user data. The shared base is AIM 4.7.7; this is an
unpublished 4.8 experimental extension, not a stable release claim.

The experiment mandate supplies bounded Auto implementation authority for these
isolated candidate files. Record actual method activation and plan in existing
`.aim/` product/evidence facilities, use available AIM helpers for native product
gates where applicable, and keep product status truthful. Reviewer approval is
not human acceptance. No external publication or global installation. The
coordinator alone owns product runtime; workers own assigned source or evidence.

The selected orchestration skill determines graph design, decomposition, agent
dispatch, task/review scheduling, recovery and continuation. AIM still determines
requirements, actual authority, evidence quality and final acceptance semantics.
Do not load the other candidate or its outputs. This experiment's explicit method
selection supersedes the consumer's pinned 4.7 orchestration choice only here.

The supplied model policy is **GPT-6 Luna / Max for every experimental agent**.
Upstream recommendations to change model do not override it. The elapsed budget
includes all work/coordination/children/reviews/fixes from first dispatch to cutoff.
Use at most three concurrent agents including coordinator, with exact scoped
ownership. Do not spawn recursive helper chains. End child work at cutoff too.

Inspect the normal product entry and maintained verification recipes, then make
the smallest useful complete result. Movement, input replay, resets and save
integrity remain quality obligations. A build, a report, a passed local test or
an offscreen render cannot prove a live playable journey. Cite what was actually
observed; retain missing proof and failures. Use repository-local fresh profiles
via `--profile-root`; never open/write the ordinary player profile.

Use `native-probe/build-experiment.sh` for the experimental native package. The
original build script remains intact: its manifest checks previous accepted
source hashes and cannot attest a new level implementation. The shared
experimental route compiles the same native app, signs it and records actual
source/resource hashes without claiming historical or new product acceptance.

At cutoff stop changes and return source paths, app/build/verification commands,
actual per-level status and evidence/limitations. No incomplete result is owner
acceptance. Independent scoring happens after cutoff without product edits.
